Python Best Practices Gopher sphere v0.1
========================================

Purpose
-------
Portable Python best-practice guidance for LLM authors, layered onto LLM Gopher
without changing engine semantics. The python-best-practices profile loads core +
python-best-practices and publishes articles, an indexed corpus, reference rule
documents, and engine-consumable example method splices.

Posture
-------
Canonical/reference (PLABEL). Grounding is the CPython data model and standard
library semantics plus the known failure classes an LLM emits from corpora. It is
not a set of fabricated project incidents. Python is secondary in this project; the
sphere is deliberately portable so an authoring LLM on any checkout can use it.

Engine reality
--------------
- `rules check` executes exactly four statically-detectable Python breaches
  (syntax, duplicate method, wildcard import, bare except) from a hardcoded
  evaluator; a sphere cannot add executed breaches without editing the engine.
- python `language-rule` documents here are reference guidance rendered by
  `rules show`, each with a deterministic trigger and concrete correction.
- examples/python-method/*.py.frag are one complete method each, the exact
  replacement_path shape `source.python.method.edit` validates before an AST-scoped
  commit (article edits.preserve-unrelated-bytes).
