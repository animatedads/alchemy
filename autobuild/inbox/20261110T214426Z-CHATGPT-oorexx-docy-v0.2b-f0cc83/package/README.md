# Alchemy DOCY Office v0.2b — native archive integration candidate

**Date:** 9 November 2026. **Qualification:** partial; real PDF/ODT provider binary run outstanding.

## What changed since v0.2a

- Added `docy_native_odt.cls`: DOCY-compatible OpenDocument access object that reuses upstream `OdtDocument`, `OdtPackageWriter` XML methods, `OdtPackageReader` block parsing, and Alchemy `ZipWriter` / `ZipArchive`.
- It performs no ZIP command-line subprocess, temporary unpack directory, or alternative ODT XML generation. The native archive writer emits `mimetype` first using method 0, and the remaining OpenDocument members via method 8.
- On read, entry `mimetype` must have local-header offset 0, method 0, and the exact ODT MIME string. Reuse the Archive library's bounded ZIP32 reader (2,000 entries; 64 MiB per entry; 128 MiB aggregate declared uncompressed data), CRC/inflate safety, name and structural validation. The ODT manifest and content member must exist.
- Hardened `DocyOfficePublisher` so publisher SYNTAX, ERROR or FAILURE conditions return STOP diagnostics with no successful path receipt.
- Added an actual-provider runner (`publish_real_office.rex`) and focused tests for the new ODT archive interface, fact propagation, and failed-provider reporting.

## Native provider run (not executed in this delivery)

Stage these **exact Alchemy components** on `REXX_PATH`:

- `packages/oorexx_pdf/src` (v0.1-dev6)
- `packages/oorexx_odt/src` (v0.1-dev1)
- `packages/oorexx_archive_v0.1-dev1/src`
- `oorexx-compress` with module level >= 4 (required by Archive)
- `oorexx_font_manager` if managed Unicode PDF font tests are selected

With the package source on `REXX_PATH`, run:

```
rexx publish_real_office.rex alchemy_shared_graph_office.docy
pdfinfo alchemy_grid_plan.pdf
pdftotext alchemy_grid_plan.pdf -
unzip -t alchemy_grid_plan.odt
unzip -p alchemy_grid_plan.odt mimetype
libreoffice --headless --convert-to pdf --outdir /tmp/odt-check alchemy_grid_plan.odt
```

The PDF generated by `PdfFlowReport` is the DOCY publication. The LibreOffice conversion in this list is **only an independent ODT compatibility check**, not the implementation of DOCY's PDF publisher. For PDF visual qualification, render PDF pages and inspect every page.

## Tests executed

Run the six ooRexx scripts through `tools/run_qualification.sh /path/to/rexx`. The new native-archive tests use injected doubles, and do not qualify actual ZIP/ODT binary interoperability. Baseline plus new tests: 107 PASS / 0 FAIL on supplied ooRexx 5.3.0 r13196.

## Preserved limitations

- PDF/ODT real-provider binaries not qualified in this runtime; sources were inspected in the Alchemy GitHub repository but could not be staged here.
- SVG assets still yield visible omission and WARN; real Writer TOC, image embedding and advanced styles not yet done.
- DOCY still permits direct mutation of graph objects outside event planning. No Storage Fabric atomic publication or cryptographic history exists yet.
- `DocyNativeOdtAccess~save` currently writes to the destination directly through Alchemy `ZipWriter`; a failed write may leave a partial file. Future transactional publication must allocate a staging object and promote on success. Do not claim atomicity.
- DOCY templates and facts remain the authoritative source; edited `.odt` files are not auto-imported into the graph.
