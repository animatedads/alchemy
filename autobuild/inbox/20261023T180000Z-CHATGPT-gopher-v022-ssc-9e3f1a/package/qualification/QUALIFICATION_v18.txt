Current workspace observation
-----------------------------
At development time the active execution filesystem reported roughly 30 GiB free and
~2.1 million free inodes; /mnt/data used roughly 98 MiB. This is evidence for the
current session only, not a universal ChatGPT workspace contract.

Exact quota regression
----------------------
A real ZIP was generated with:
  compressed ZIP size: 31,593,716 bytes (~30.1 MiB)
  uncompressed member size: 161,480,704 bytes (154 MiB)
  expansion ratio: 5.111
  declared workspace limit: 62,914,560 bytes (60 MiB)

Preflight read the ZIP central directory without extraction and returned:
  operation_status: HANDOVER_ADVISED
  finding: INSUFFICIENT_BYTES
  advice.action: PREPARE_HANDOVER
  advice.do_not_extract: true

This result was based on the declared session quota even though host df had far more
physical free space.

Materialisation boundary
------------------------
When an expected file is absent, Gopher does not infer a /mnt/data path from its title.
The result names the required host capability as `files.materialize`. If expected
materialisation plus reserve does not fit, the result advises handover before asking the
host to materialise it.

Handover/recovery
-----------------
workspace.handover.frame is read-only. It can capture current environment, active spheres,
artifact bytes/SHA-256, task and next action, and lists missing continuity fields.
workspace.context.recoverability advises handover when durable setup/sphere/qualification/
changelog evidence is insufficient; model conversational recollection alone is not treated
as durable recovery evidence.
