## Universal Codex execution contract
- Implement in **our** Alchemy/ooRexx components and Wire semantic applications; no Postfix, Dovecot, slapd, Nginx, external webmail, off-the-shelf CMS, or replacement MCP server. Platform OS, OpenSSL and systemd remain acceptable mechanics, not substitute product authorities.
- Inspect `https://github.com/animatedads/alchemy`, component READMEs, tests, revision provenance and newer Library deliveries; use the latest accepted exact revision, not an assumed repository-folder suffix. Record selected versions and SHA-256s. Mark unknown capabilities UNKNOWN and then write missing functionality.
- Respect `GIT_SUBMISSION.md` for real source publication: use `python3 tools/alchemy_submit.py --repo . --package ... --submitted-by CODEX --json` for eligible component deliveries. Do not open or merge ad-hoc source PRs or publish secrets. Separate independent component packages; no vendored copies of sibling Alchemy trees.
- Implement real source **and executable tests**; give complete files/managed delivery with manifest and evidence. Don't return only a plan, fake health endpoint, stub, pseudocode, or test marked PASS by echo.
- Work autonomously on routine choices. Only stop for truly external permissions/secrets/host facts or explicitly gated destructive/live cutover actions. Never claim live qualification from fixtures. No unapproved production service changes, credential issuance or DNS rewrites. Maintain rollback and operator-approval gates.
- Build and test the isolated component(s) and report `PASS`, `FAIL` and `NOT_RUN` with evidence and constraints. Keep network access/authz secrets and raw mailbox contents out of logs.
