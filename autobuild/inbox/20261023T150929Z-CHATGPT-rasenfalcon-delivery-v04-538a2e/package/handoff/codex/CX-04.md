# CX-04 — Our SMTP and IMAP production mail service plus durable mailbox

**Priority:** P0  
**Scheduling:** After CX-01 and identity integration; can build source in parallel  
**Backlog coverage:** RF-014–RF-019  
**Repository:** `animatedads/alchemy`

**Mission:** Produce an actual receiving/sending service entirely from our `oorexx_smtp_secure_stack` and `oorexx_imap` lines, backed by existing Storage Fabric/NoSQL/Queue semantics. The IMAP dev10 server is **partial**: do not imply its client methods constitute a complete server.

**Build:** SMTP inbound port 25, EHLO/STARTTLS/recipient validation, durable spool/classification into `INBOX` vs `INBOX-UNSIGNED`, delivery/retry/DSN and authorized signed outbound submission on 587; IMAP TLS listener 993, LDAP auth, SELECT/EXAMINE, FETCH/UID FETCH literal bounds, APPEND, STORE flags, SEARCH, COPY/MOVE/EXPUNGE UID semantics and stable `(account,mailbox,UIDVALIDITY,UID)` after restart; safe concurrency/IDLE only when real and advertised. Implement missing server commands in owned IMAP rather than falling back to Dovecot or narrowing tests.

**Security:** Mandatory signing policy, no open relay, MIME size/complexity limits, mailbox ACL and quotas; SPF/DKIM/DMARC/DNS/PTR planned without inventing DNS state. Under SMTP review, preserve existing post-DATA `250` durability and retry semantics.

**Exit:** Controlled real SMTP client submits bytes, mail appears durably in correct IMAPS mailbox, correct unsigned classification, reads/flags/moves work across restart. Invalid relay/auth/TLS/signer recipients are rejected. Large attachments bounded, mailbox UID invariants proven.
