# Review of the supplied native gzip sources

Two source variants were examined:

- loose `native_gzip_fixed_huffman(1).rex`, SHA-256 `fa96ed6a7581862070e37c0d160ee7479ff587433f3e588d48b21fce1323bb16`;
- decompressed `native_gzip_fixed_huffman_exposefix.rex(1).gz`, SHA-256 `12e3501c7514b890e138419a8bc70e8b46ae06a037b009653c2ac0d7aefd96b8`.

The exposefix variant differs in exactly two executable lines: `emitLengthDistance` and `emitFixedSymbol` were changed to `procedure expose BW_OUT BW_BUF BW_BITS`. Those are real fixes. The loose variant fails fixed-Huffman compression because the nested procedure loses the bit-writer variables and eventually tries to use symbolic `BW_BITS` in arithmetic.

The `LZ77` description is also real implementation, not a dependency. `findMatch()` performs a bounded search over up to 32 KiB of preceding data, considers at most 48 candidate prefix hits, caps matches at DEFLATE's 258-byte maximum, and emits normal length/distance pairs.

## Correctness / ooRexx issues repaired

1. Bit writer state depended on procedure `EXPOSE`; now state is owned by `NativeBitWriter`.
2. Bit reader state likewise moved out of exposed global variables into `NativeBitReader`.
3. Binary equality used ordinary Rexx comparison in several places; binary protocol checks now use strict comparison.
4. `byteAt()` returned zero for out-of-range accesses, which could turn truncation into fabricated input; bounds now fail closed.
5. gzip FHCRC was skipped rather than checked; it is now validated.
6. gzip optional-field bounds are checked before advancing parser state.
7. trailing data / concatenated members are explicitly rejected by the bootstrap codec instead of being silently ignored.
8. reserved DEFLATE distance codes 30 and 31 are rejected immediately.
9. CRC32 used eight bit-level string shifts per input byte. The replacement is a pure ooRexx 256-entry table implementation.
10. overlapping DEFLATE match copying appended one byte at a time. It now expands the already-decoded distance-sized seed in one bounded operation.
11. file opens, output writes and CLI errors are checked rather than assuming success.
12. reusable codec logic no longer calls `EXIT`; the CLI owns process exit behaviour.
13. public entry points use `USE STRICT ARG` and live behind an explicit provider API.
14. the ambiguous `ZIP` alias for gzip has been removed from the new CLI.

## Deliberately retained

- pure ooRexx implementation;
- fixed-Huffman encoder;
- stored-block baseline;
- the original bounded LZ77 strategy rather than replacing it with an opaque optimizer;
- whole-byte String representation for binary data;
- explicit dynamic-Huffman gap.

## Compatibility evidence

The new provider:

- decodes the supplied `sample_crc_fixed(1).gz` (9716 bytes output);
- decodes gzip generated by the exposefix source;
- emits gzip decoded successfully by the exposefix source;
- emits gzip accepted by the system `gzip -t` qualification oracle.
