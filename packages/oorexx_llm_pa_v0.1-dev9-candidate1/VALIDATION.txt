- every ability: READ_ONLY, mutating=false, eventable=true
- actual ADDRESS SYSTEM is executed from a floating ooRexx Method with LlmPaMachineCheckSecurityManager attached using Method~setSecurityManager
- SecurityManager independently validates the full command shape: timeout 20 <configured sshnode helper> <delegated ED209 node> '<known read-only probe>'
- exact command must additionally match the per-invocation allowlist
- defense-in-depth denies shell composition/redirection and mutators including pipe/redirection, --transfer, rm/mv/cp/touch/mkdir/rmdir/ln/unlink, sudo/kill/chmod/chown, filesystem/device mutation, service start/stop/restart, and QueueBash mutation
- stdout/stderr are captured directly into Rexx arrays; no > or >> output files are used
- process command lines are used internally for classification but raw process arguments are redacted before PA/model evidence leaves the ability
- queue_status uses aggregate `queue stats`; raw QueueBash job payloads/commands are not given to Gemma
- file_status is metadata-only and rejects traversal and sensitive path classes

Deployment observation:
- observes QueueBash version, installed queue script stat/hash, read-only systemd active state, and deployment-like process presence/elapsed time
- active deployment process under 300 seconds -> IN_PROGRESS
- active deployment process at/over 300 seconds -> STUCK_SUSPECTED
- no active deployment process + expected installed version match -> DEPLOYED
- no active deployment process + expected version mismatch -> NOT_DEPLOYED_OR_STALE
- no expected version + quiet identifiable installation -> INSTALLED_QUIESCENT
- this is observation only and cannot deploy, repair, restart, cancel, clean up, or transfer anything

Eventable semantics:
- an Alarm-fired PA turn may request one of the same machine observations
- the triggering Alarm is still one-shot and ends when it fires
- machine observation cannot create recurrence
- Gemma may decide to finish or explicitly request a NEW Alarm under the existing Alarm authority path
