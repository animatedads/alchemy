Security boundary implemented
-----------------------------
1. Accepted socket numeric source address is checked before any HELLO read.
2. Application allowlist is exact canonical dotted-quad IPv4 only. CIDR,
   hostnames, IPv6, leading-zero forms, malformed/out-of-range octets and
   0.0.0.0 are rejected.
3. Re-registering a peer rebuilds the aggregate source set; removed addresses
   do not remain admitted to pre-auth processing.
4. Selected peer identity is checked against its own IP allowlist again before
   cryptographic authentication.
5. HELLO and CHALLENGE are mutually HMAC-SHA-512 authenticated.
6. Client/server random nonces plus the complete authenticated transcript and
   PSK derive independent C2S/S2C encryption keys, MAC keys and nonces.
7. PROBE, DELIVER, HEALTH and RESULT bodies are ChaCha20 encrypted and
   HMAC-SHA-512 authenticated using encrypt-then-MAC. Authentication is checked
   before decrypt/application processing.
8. Receiver channel/ACL authority and durable transfer-id idempotence remain
   authoritative above transport admission.

The design is PSK-based and does NOT provide forward secrecy. See
SECURE_TRANSPORT.md.

OCI two-node deployment contract
--------------------------------
Prefer private VCN addresses. At the OCI network layer use a narrow ingress
rule for the Queue Fabric TCP port from the reciprocal peer address /32; do not
open that port from 0.0.0.0/0. At Queue Fabric itself bind the trusted peer to
the same exact numeric private IPv4. See OCI_TWO_NODE_DEPLOYMENT.md.

Allocator boundary
------------------
Transport crypto remains a Queue Fabric concern. A node that offers this path
may advertise a hard ability such as QUEUE_SECURE_TRANSPORT_V2; jobs that depend
on it should require that ability. Capacity or ranking cannot replace a missing
hard requirement.

Secret boundary
---------------

raw transport key material. The compatibility constructor still accepts keyHex;
production wiring should resolve that material from Secret Broker by reference.
Secret-reference-native registration/rotation remains a separate increment.
