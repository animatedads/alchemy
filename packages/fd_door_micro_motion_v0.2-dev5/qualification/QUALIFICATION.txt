FD Door Micro Motion v0.2-dev5 qualification
============================================

Purpose of the dev5 rebase
--------------------------
v0.2-dev5 rebases fresh FD execution onto Migratable Job v0.2.4 managed
initial placement.  The normal NEW path no longer uses the dev4 FD-specific
authority receipt.  Instead the FD application carries a native
JobPlacementRequest, MigratableJobManagedPlacementTool obtains and verifies the
Job-to-Node v0.6 lease, and FDDoorMicroMotionPlacedStartExecutor injects only
that already-verified lease before entering the standard
migratable.job.start/1 starter.

Standard APIs
-------------
Migratable Job main API:             migratable.job/0.2
Standard starter:                    migratable.job.start/1
Managed initial placement:           migratable.job.placement/1
Placement audit receipt:             migratable.job.placement.receipt/1
Migratable Job implementation:       v0.2.4
Job-to-Node implementation:          v0.6

The placement audit store is evidence, not placement authority.  Job-to-Node
ownership state is persisted by JobNodeDurableJournal.  A failed or ambiguous
START retains the verified placement until an explicit RELEASE after runtime
state has independently been established.

Deployment rule
---------------
For the 00:00-05:00 night campaign, ed209a holds the canonical durable
Job-to-Node journal.  C/D/H/I prepare their measured node/source probes and
launch specifications; ed209a performs standard managed placement against the
same durable journal; the exact resulting durable state snapshot, probe/spec
and audit evidence are supplied to the assigned worker; the worker performs
CHECK then START through start_fd_managed.rex.

Operators do not type a placement ID or ownership epoch and do not use a
custom FD authority receipt.  run_fd_worker.rex is payload machinery only.
The legacy ed209e TP00009 job is outside this rebase and must remain untouched.
