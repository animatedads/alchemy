# NoSQLServer v0.78 — Alchemy Objects v0.5.1 STANDARD adoption

v0.78 advances the v0.77 service-boundary inheritance to the explicit Alchemy
Objects adoption contract. Stateful service/facade objects still derive through
`NoSQLAlchemyObject`; rows, scalar values, geometry values, parser/expression
nodes and other hot-path data remain deliberately lightweight.

## Required base

Runtime dependency: **Alchemy Objects v0.5.1** plus its existing
`oorexx_crypto_v0.1` dependency.

v0.5.1 retains the `ALCHEMY-HOUSE-OBJECT-0.5` structural standard while refining
the v0.5 reserved-name rule: business `version()` and `schema()` APIs are legal,
while security/evidence/identity/lifecycle/telemetry/contract behavior remains
non-shadowable.

## STANDARD metadata

`NoSQLAlchemyObject~initNoSQLAlchemy` supplies the v0.5 STANDARD metadata:
PURPOSE, PACKAGE, PACKAGE_VERSION, AUTHORSHIP, STANDARDS and
DESIGN_LIMITATIONS. PACKAGE is generated by the Alchemy base from the concrete
class package.

Every migrated public service object is exercised through
`AlchemyAdoptionVerifier~verify(object, "STANDARD")`.

`SECURE_READY` is never implied. A host may configure a sealer and capability
authority, but an unconfigured object is still a valid STANDARD service object
and must fail SECURE_READY admission.

## Migrated service boundary

- FileDatabaseEngine
- ObjectDatabaseEngine
- JsonDatabaseEngine
- SQLiteDatabaseEngine
- GeoPackageDatabaseEngine
- FederatedDatabaseEngine
- NoSQLServerRuntime
- NoSQLServerSQL
- DatabaseTransaction
- NoSQLDatabaseCoreAdapter

The SQL/storage/Geo/JSON/Unicode semantics are unchanged from v0.77/v0.76.
