NoSQLServer v0.85 validation
Date: 2026-10-06

Change under qualification
--------------------------
World intention qualification exposed that v0.84 INTEGER validation used
DATATYPE(value,"W"), which is sensitive to the active Rexx NUMERIC DIGITS and
could reject valid 10-digit integer text.

v0.85 introduces NoSQLIntegerSupport and routes column coercion,
DatabaseValue~integer, and prepared INTEGER rendering through lexical integer
validation. INTEGER relational comparison now uses exact sign/magnitude
comparison rather than ambient numeric coercion.

No World source data is modified. A World Population DECIMAL projection used
while qualifying against v0.84 remains a documented compatibility workaround,
not a domain-type assertion.

v0.85 forcing evidence
----------------------
The regression creates country.population as INTEGER and proves:
- INSERT of 1277558000 succeeds;
- the exact text 1277558000 round-trips unchanged;
- predicates and ordering over 10-digit INTEGER values are exact;
- DatabaseValue~integer accepts the 10-digit value;
- prepared parameter rendering preserves the value;
- fractional and exponent spellings remain invalid INTEGER input;
- signed/zero-padded integral spellings remain valid.

No new 32-bit limit is imposed. NoSQLServer INTEGER remains its existing
unbounded integral-text domain; this release removes the ambient-precision
failure rather than narrowing INTEGER semantics.
