Defect reproduced
-----------------
Against stock v0.70, a SQL UPDATE targeting a registered Virtual RYTA v0.11
external Algorithm Relation returned:

  NOTEXECUTED NOTFOUND Table not found: ryta_actions

The relation itself existed and was queryable.  Federation had routed every
non-OBJECT mutation into FileDatabaseEngine instead of resolving the owning
provider.

v0.71 repair
------------
FederatedDatabaseEngine now resolves table ownership OBJECT -> FILE -> external
before table-scoped mutation dispatch.

  owner absent                         -> NOTFOUND
  owner lacks requested mutation       -> SQLUNSUPPORTED
  owner implements mutation            -> delegated result

The same owner resolution is used by selectWhere and index-candidate estimation.
Feature flag:

  FEDERATED_PROVIDER_NEUTRAL_MUTATION_DISPATCH
