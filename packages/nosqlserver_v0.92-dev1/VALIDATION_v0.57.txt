NoSQLServer v0.57 validation
============================

Focus
-----
Frozen read-only snapshots of live object tables.

Snapshot semantics
------------------
- ObjectTableStorage~freeze() copies mapped DatabaseRow values once.
- ObjectDatabaseEngine~registerSnapshot(name, collection, mapping) registers a
  frozen table directly.
- ObjectDatabaseEngine~snapshotTable(sourceName, snapshotName) freezes an
  already registered live object table.
- Snapshot rows participate in ordinary SELECT, WHERE, ORDER BY, JOIN and
  aggregate paths through the same table port.
- Subsequent mutations of the original ooRexx objects are not visible in the
  snapshot.
- Snapshot rows are copied when read so SQL consumers cannot mutate the frozen
  backing rows accidentally.

Mutation honesty
----------------
- INSERT on snapshot: SQLUNSUPPORTED
- UPDATE on snapshot: SQLUNSUPPORTED
- DELETE on snapshot: SQLUNSUPPORTED
- No transaction capability is advertised or implied.
- A snapshot is a consistency/read model, not a fake unit-of-work transaction.

Federation
----------
- FederatedDatabaseEngine delegates registerSnapshot/snapshotTable to its object
  catalog, so frozen object tables can coexist and join with file-backed tables.
- msqlshim remains untouched.
