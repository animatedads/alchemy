Defect reproduced
-----------------
Against untouched v0.71, this valid two-table INNER JOIN predicate:

  ON l.order_id=r.order_id AND l.product=r.product

returned:

  NOTEXECUTED SQLPARSEERROR Unknown or ambiguous JOIN right column

The specialised two-table path used the first '=' character as a structural
split and treated the entire remaining expression as one right column name.
The alias-aware inner-chain evaluator already parsed and executed the complete
predicate correctly.

v0.72 repair
------------
The SQL predicate parser is now authoritative for INNER JOIN ON semantics.

  one plain column equality
      -> existing specialised two-table path retained

  general predicate with a safe equality connector
      -> alias-aware hash candidate generation
      -> complete ON predicate evaluated on each combined candidate row

  general predicate without a safe equality connector
      -> candidate-pair predicate evaluation

Equality is therefore a join access-path optimisation, not a grammar
restriction.  No provider identity or structured-source semantics participate
in this decision.

Feature flag:

  INNER_JOIN_GENERAL_ON_PREDICATE

Access paths:

  INNER_HASH_CHAIN        safe equality connector used
  INNER_PREDICATE_CHAIN   general predicate fallback
