# IBM 4361 / OS/360 MVT ooRexx — safety4 handover

## Status
This is an **in-progress safety checkpoint**, not a release. It advances the
real-MVT CPU frontier by implementing only the opcode proved by the guest at
the safety3 stop.

## Architectural boundaries that remain mandatory

- **Freeze files** are durable, externally verifiable whole-machine evidence
  and replay artifacts.
- **Journal-pointed state** is live in-process history for rewind/fork/diff/retry.
- A journal may reference a freeze checkpoint as a base, but does not replace
  or redefine the freeze format.
- The guest-visible **IBM 3215 channel console** is separate from the physical
  **IBM 4361 operator/control console**.

## Safety3 frontier reproduced exactly

The first non-OK instruction was captured without guessing:

- IA `FF717E`
- ICOUNT `511635`
- instruction bytes `8A3000021B43`
- opcode `8A`
- PSW `0004000060FF717E`
- R3 `000001D8`

Hercules 2.17.1 source identifies X'8A' as SRA / Shift Right Single. Its
implementation uses the rightmost six bits of the effective operand address as
the shift count, sign-extends right shifts, and sets CC from the signed result.

## Journal-pointed live trial proved

A disposable trial tree exposed the executor's private object-method install
through a narrow `installLiveMethod()` seam. The real MVT state was then put
under `IBM4361JournalSession` control at the exact pre-instruction point.

Evidence in `evidence/mvt_sra_journal_retry.log`:

- first try: `UNSUPPORTED`, state unchanged at FF717E / 511635 / R3 000001D8
- install object-scope `OP8A`
- rewind: exact pre-instruction state restored; patch remains installed
- retry: `OK`, IA FF7182 / ICOUNT 511636 / R3 00000076 / CC2
- guest continues for 128 more instructions

This satisfies the acceptance rule: the old diagnostic did not merely vanish;
the exact historical state was retried and made architecturally plausible
forward progress.

## Permanent source promotion

`IBM370Executor.cls` now includes:

- X'8A' in the native opcode set;
- permanent `OP8A` SRA semantics;
- public `installLiveMethod(methodName, source)` as an object-scope trial seam.

The seam deliberately does **not** make the executor depend on the optional
Journal Pointed State package. It only exposes ooRexx object-scope method
installation so the external recovery coordinator can patch and rewind.

New tests:

- `tests/test_cpu_sra.rex`
- `tests/test_executor_live_method_seam.rex`

Full suite result: **70 sources compile; 31 runtime tests pass**.

## Probe media acceleration

The supplied MVTRES.350 uses compressed CCKD tracks and the pure-ooRexx zlib
path is slow enough to make repeated archaeology impractical. For the probe
only, an uncompressed CCKD container was generated from the same logical
tracks. It is **not** part of this package.

`evidence/probe_media_equivalence.txt` proves byte identity of every available
logical track:

- 3252 non-null tracks checked
- 4424 null tracks
- logical SHA-256
  `ce0c49bf558074fb9860f680aa9b6284b4fd5c59634d405f988ddc37ea69ca65`
- original MVTRES.350 SHA-256
  `095b44517a85bfdd65764d22af8378e30c1437cd8539ed582e1eb45fea7c5b49`

Historical media remains external and is not vendored.
