# IBM 4361 / OS/360 MVT ooRexx — safety5 handover

## Status
This is an **in-progress safety checkpoint**, not a release. It advances the
real-MVT CPU frontier by implementing only the instruction proved at the
safety4 stop: System/370 CVD / Convert to Decimal, opcode X'4E'.

## Architectural boundaries that remain mandatory

- **Freeze files** are durable, externally verifiable whole-machine evidence
  and replay artifacts.
- **Journal-pointed state** is live in-process history for rewind/fork/diff/retry.
- A journal may reference a freeze checkpoint as a base, but does not replace
  or redefine the freeze format.
- The guest-visible **IBM 3215 channel console** is separate from the physical
  **IBM 4361 operator/control console**.

## Safety4 frontier reproduced exactly

The permanent safety4 source again reached the same first non-OK instruction:

- IA `FF71B0`
- ICOUNT `511763`
- instruction bytes `4E10D677F332`
- opcode `4E`
- PSW `00040000B0FF71B0`
- R1 `0000000D`
- effective operand address `FFD470`
- condition code `3`

Independent Hercules Hyperion source evidence identifies X'4E' as CVD /
Convert to Decimal. Its implementation sign-extends the 32-bit source GPR,
converts that signed value to packed decimal, and stores the low eight packed
bytes at the RX effective address. The condition code is not changed.

## Journal-pointed live trial proved

A disposable object-scope `OP4E` trial was installed through the existing
`installLiveMethod()` seam at the exact historical pre-instruction state.
Evidence is preserved in `evidence/mvt_cvd_journal_retry.log`.

Exact retry sequence:

- first try: `UNSUPPORTED` at IA `FF71B0`, ICOUNT `511763`; R1, operand and CC unchanged;
- object-scope `OP4E` installed;
- journal rewind restores IA `FF71B0`, ICOUNT `511763`, R1 `0000000D`, operand
  `0000000000000000`, and CC3 exactly while the method remains installed;
- retry: `OK`, IA `FF71B4`, ICOUNT `511764`;
- operand at `FFD470` becomes packed decimal `000000000000013C`;
- R1 remains `0000000D` and CC remains 3.

The guest therefore made architecturally plausible progress from the exact
historical state rather than merely losing a diagnostic.

## Permanent source promotion

`IBM370Executor.cls` now includes:

- X'4E' in the native opcode set;
- permanent `OP4E` CVD semantics;
- signed 32-bit conversion to an 8-byte / 15-digit packed-decimal result;
- C sign nibble for zero/non-negative values and D for negative values;
- no condition-code modification.

New/permanent focused regression:

- `tests/test_cpu_cvd.rex`

The pre-promotion live-method regression is retained as archaeology evidence:

- `tests/test_cpu_cvd_live_trial.rex`

It covers zero, positive/negative one, both signed 32-bit extremes, unchanged
condition code, normal RX storage, and indexed/base RX addressing.

## Permanent-source real-MVT frontier

After permanent CVD promotion, real MVT again follows the deterministic path,
executes CVD at FF71B0, and stops immediately at the next unsupported
instruction:

- IA `FF71B4`
- ICOUNT `511764`
- instruction bytes `F332D643D67C`
- opcode `F3`
- PSW `00040000B0FF71B4`
- 3215 output count remains zero

Independent Hercules opcode/general instruction source identifies X'F3' as
**UNPK / Unpack**. That identification is recorded only to define the next
frontier. **UNPK is deliberately not implemented or trialled in safety5.**

## SSC status

The governing handover requires the exact
`oorexx_semantic_source_control_v0.2.2` baseline for permanent source
qualification. The supplied continuation roll-up contains v0.2.3, not v0.2.2.
A Library search for the exact v0.2.2 artifact and broader semantic-source-
control terms did not recover that package. No silent substitution was made.

Therefore the **v0.2.2 SSC qualification remains explicitly pending**. This is
the only known checkpoint qualification item not executable from the supplied
or recoverable artifacts.
