FD Door Micro Motion v0.2-dev8 qualification
============================================

Scope
-----
v0.2-dev8 is a video-processing hardening release.  It keeps the visual-only
F11 door analysis boundary and the v0.2-dev7 multi-timescale temporal model,
then adds coherent local source-file stability fencing using ooRexx POSIX
Foundation v0.1-dev1.

The scientific path remains blind to audio.  Visual events are observations of
mechanical/door response only; unavailable geometry, camera relocation,
photometric instability, excluded scene intervals, and failed reacquisition are
not converted into negative door evidence.

Source-file stability added in dev8
-----------------------------------
Production tools/run_fd_worker.rex constructs FDSourceStabilityGuard using
PosixGapFactory.  The guard requires coherent POSIX stat/lstat evidence and
binds local execution to:

  target device/inode/type
  target size
  target mtime seconds + nanoseconds
  target ctime seconds + nanoseconds
  lstat identity/type/times
  raw symlink target (when the source path is a symlink)

The source must be unchanged across the initial quiet interval.  It is checked
again after FFmpeg opens the decoder, periodically while decoding, before a
migration checkpoint, and before declaring successful completion.

Changing/growing/truncated/replaced/retargeted input fails closed as one of:

  SOURCE_NOT_STABLE_AT_START
  SOURCE_MUTATED
  SOURCE_STAT_FAILED

Device/inode identity is local provenance only.  source_evidence_ref remains
the portable cross-node content identity.

A failed source-stability preflight writes control provenance to
state/source.guard.failure.tsv and DOES NOT overwrite an existing scientific
.run.tsv.  This specifically protects an already-valid source-side run artifact
when a destination RESUME discovers an unstable local copy before opening
FFmpeg.

Harness boundary
----------------
The core tests were run individually and passed as listed above.  A single
aggregate run_tests.sh invocation hit the outer execution-time limit while
entering the real POSIX-guarded worker after the first five tests; that worker
then passed when run individually (11.72 s).  The long real managed-starter E2E
test was not used as a dev8 qualification claim because it exceeded this
session's single-command execution budget.  The lower-level real FFmpeg worker,
scientific migration equivalence, standard HANDOFF, and v0.2.5 remote-start
contracts were all exercised separately.

The full TP00000-TP00003 night corpus is not present in this packaging
container and was not re-analysed here.  Real-corpus qualification remains the
ED209 campaign task.  No thresholds were changed on the basis of audio.
