dev8 live-result correction:
  The dev8 live script reported:
    USB enumeration OK: 5-1 CAFE:F1D0
    no HID interface

  That result is NOT accepted as evidence about the dev8 presenter.  The same
  target diagnostic log later identifies the current presenter PID failing:
    UDC core: USB Raw Gadget: couldn't find an available UDC or it's busy
    misc raw-gadget: fail, usb_gadget_register_driver returned -16

  Therefore the script had inspected a CAFE:F1D0 generation that pre-dated the
  current presenter.  The actual dev8 presenter did not acquire dummy_udc.0.

dev9 qualification repairs:
  - selected UDC must be idle before presenter launch;
  - processes holding /dev/raw-gadget are reported when a UDC is unexpectedly
    active;
  - presenter writes an out-of-band ready marker only after Raw Gadget RUN
    succeeds;
  - pre-existing CAFE:F1D0 devices are snapshotted as sysfs-name:devnum;
  - only a new generation token can satisfy enumeration;
  - cleanup escalates INT -> TERM -> KILL;
  - provider trace can be persisted directly to a file, avoiding stdio
    buffering at a blocked ioctl;
  - tests/test_live_generation_guard.sh simulates stale 5-1/devnum 2 followed
    by a new 5-1/devnum 3 and passes only the latter.

Provider status:
  The dev8 EP0 direction repair remains in place:
    IN request                  -> EP0_WRITE(response)
    OUT request, data length 0  -> EP0_READ(0)
    OUT request, data length >0 -> one EP0_READ(length), no second EP0 ioctl

  This is consistent with the Raw Gadget UAPI/reference keyboard behavior, but
  it still requires a clean presenter-owned target generation before acceptance.
