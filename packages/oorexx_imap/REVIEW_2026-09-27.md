## Repairs made

1. Mutable collection ownership
   * response line/literal arrays are returned defensively;
   * command result arrays are copied on construction and read;
   * UID-set fields/ranges are copied rather than aliased;
   * session capabilities and selected mailbox state return snapshots;
   * local-index terms/hits and semantic-selector stages return copies.

2. Numeric context
   * UID, literal length, byte-count and selected protocol counters use explicit
     `numeric digits 30` at internal conversion/calculation boundaries.
   * regression exercises large UID values while the caller uses DIGITS 9.

3. Guard ordering / failure behavior
   * optional literal sink factory is tested for `.nil` before method dispatch;
   * token-tail parsing checks length before `right(1)`;
   * literal source rejects zero/non-whole read sizes.

4. Server responsibility/authority
   * added separate authentication, mailbox-authority and mailbox-provider
     contracts rather than making authentication imply access;
   * LDAP adapter attributes principal only;
   * delivery-managed INBOX classifications remain owned by delivery semantics;
   * partial server advertises an explicit vendor core capability, not full
     IMAP4rev1.

## Qualification boundary

Required package tests cover the legacy client contract plus review regressions,
server core and LDAP adapter shape. Optional native/storage/database/live network
integrations remain separately gated and are not promoted by this review pass.

5. Current Storage Fabric compatibility
   * Storage Fabric dev23 no longer contains the legacy `StorageSemantic.cls`;
   * dev9's projection therefore failed to load against the current reviewed Storage candidate;
   * dev10 removes that hard dependency from the normal projection and isolates the old semantic-provider adapter in `ImapStorageFabricLegacySemantic.cls`;
   * current Storage Fabric dev23 literal/projection tests pass on r13196.
