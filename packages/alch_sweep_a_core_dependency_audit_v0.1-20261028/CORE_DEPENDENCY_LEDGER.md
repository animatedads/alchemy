## Executive verdict

There is substantial producer source on GitHub, **not a single qualified, accepted, recursively resolvable platform snapshot**. Four classes of problem are repeatedly visible: exact import paths to historical directories absent from Git, source and packaged/Library revisions being treated as synonyms, protocol/version identities that have moved while consumers remain pinned, and producer owners not represented by Rasen Falcon component lanes. A checkout is not acceptance; a README's local PASS is not a cross-site acceptance certificate. No source or running service was changed in this audit.

**Acceptance evidence boundary:** the authenticated read-only Semantic Source Store `source_get_package` failed with `SOURCE_PACKAGE_FAILED` for `oorexx_crypto`, `oorexx_crypto_v0.8.3` and `oorexx_xtp` roots; Rasen Falcon `sphere_check` failed with `SPHERE_CHECKER_UNAVAILABLE` on Registry, Queue, Storage and SSC spheres. Accordingly, **actual store-accepted source hashes and complete dependency closures are unverified**. Version labels below distinguish Git HEAD, package's own qualification claims, development candidates, and *verified local artefact hashes*. The Rasen Falcon lane catalogue and requests provide ownership and work evidence, not source acceptance.

## Source evidence and resolution tests

Relevant source paths were checked directly, with README, `integration.json`, `PACKAGE.json`, `DEPENDENCIES.json`, sample `::requires`, and native Makefiles read where present. In particular, the [Queue Fabric `integration.json`](https://github.com/animatedads/alchemy/blob/0998d081f0efff18231f929cc4d4714ea7243de8/packages/oorexx_queue_fabric_v0.9-dev6/integration.json) hard-pins `packages/runtime_registry_v0.12/src`, `packages/oorexx_work_load_units_v0.6/src`, `packages/alchemy_objects_v0.5/src`, `packages/nosqlserver_v0.77/src`, and `packages/oorexx_queue_fabric_v0.8.2/src`: **all five are absent at those exact paths** at audited Git HEAD. The legacy `packages/oorexx_crypto_v0.1/src/crypto.cls` **does exist**, but is older than current Crypto 0.8.3. This is a reproducibility issue with exact checkout, not proof of API incompatibility.

`ObjectQueueSocketTransport.cls` line 1038–1042 `::requires` `ObjectQueueChannels.cls`, `ObjectQueueCrypto.cls`, `socket.cls`, `streamsocket.cls`, `AlchemyObject.cls`; `ObjectQueueWLU.cls` line 113–114 requires broker + `WorkLoadUnits.cls`; `WLUFastMac.cls` line 101 requires generic `crypto.cls`; `WorkLoadUnits.cls` line 1421–1422 requires `WLUFastMac.cls` and `AlchemyObject.cls`; `Runtime Registry` `AbilityWLU.cls` line 296/298 requires `RuntimeRegistry.cls`/`WorkLoadUnits.cls`; `SemanticSourceControl.cls` line 3239 requires its own `src/crypto.cls`. **Unqualified filename resolution and multiple crypto.cls authorities make execution dependent on ordered `REXX_PATH`, not just a component name.**

The supplied Debian artifact was *inspected without installation*. `sha256sum` equals XTP's r13196 manifest pin. ELF inspection shows `librexx.so.4 -> librexxapi.so.4` plus libc, C++ and usual platform libraries; `librxmath.so.4` needs libm. The Debian archive also contains `librxsock.so.4`. Foreign Runtime and XTP native modules must be built/qualified separately and cannot be inferred from that interpreter archive.

## Authority decisions required (no implementation assigned here)

1. **One accepted revision record per provider**: package ID, semantic API, source SHA, ABI/runtime profile, qualification evidence and publication destination must be immutable; Git HEAD and Library ZIP are separate witnesses. Require `source_get_package` to resolve a full locked graph before promoting the producer.
2. **One authority per truth**: Runtime Registry controls code/ability generation, WLU controls work economics, Job-to-Node controls placement, Storage Fabric controls object/replica truth, Memory Fabric controls block ownership, Queue Fabric owns durable delivery receipts, XTP owns physical carrier and context, Socket Provider acquires sockets, ConnectSelector selects invocation mode. Gopher records navigable provenance; SSC records semantic accepted source; Autobuild publishes/test-receipts, none replaces another.
3. **Do not merge BashQueues with Queue Fabric** just because both say queue. Their API, persistence and ownership boundaries differ.
4. **Require immutable `::requires`/native edges** (qualified `REXX_PATH`, `.so` soname/dependency fingerprints, host ABI) instead of silently using the newest versioned directory or vendoring parallel cryptographic authority.
5. **Ownership map**: xtp = CLAUDE (existing); storage-replica-repair = CHATGPT (existing); queue-fabric, connect-selector, memory-fabric, autobuild, llm_gopher = existing lanes but currently no active owner shown in listing; Runtime Registry, Foreign Runtime, Crypto, Work Load Units, Event Runtime, Single Time Service, SSC = **no corresponding lane found**. Norm/QUIC and rxsock6 all link `oorexx_socket_provider`; establish one base-provider integration authority with child adapters, without unapproved code changes.
