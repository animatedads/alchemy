Architecture: Tom Dyer. Coding and local qualification: ChatGPT.

## Status and authority

A trusted owning-MU ooRexx launcher, process lifecycle and image staging interface. **Not a booted MI image, not a registered grid, and not a finished item 3.** This is an additive component for Claude's single controller. It does not implement placement, leases, identity issuance, service publication, RTO2 dispatch or XTP routes. No production configuration or keys changed. See grid.plan, grid.rules R1–R6, ed.controller, ed.work, ed.identity, ed.integration and xtpd lifecycle. R1 covers cats2 only; R2 SSH remains untouched; R3 Jammy build environment; R4 placement external; R5 rebuild; R6 limited ed209k scope. No work on other hosts.

## Package contents

- `src/MiLauncher.cls`: MiLaunchSpec, MiChildBackend, MiLauncher; ooRexx owns start/observe/stop, capacity and logging. Uses existing ProcessRunner, NativeObservedProcess and pidfd, no numeric PID signalling. Only trusted host code uses exitSources to register handles in the existing mux; never expose these handles to a proposal. No automatically started background threads or second controller.
- `bin/mi-namespace-exec`: fixed argv-only helper using existing util-linux unshare, separate PID/mount/UTS/IPC/network/user namespaces, private mount propagation, per-incarnation root, /proc mount, kill-child on supervisor exit. Requires a dedicated nonroot account, no automatic fallback to ordinary execution. A user namespace is not a complete hostile-code sandbox; no production multi-tenant isolation claim. The approved root, its ancestry and helper must be protected from untrusted changes, without host mounts/credentials or symlinked internal paths. Resource ceilings, seccomp, capability dropping, read-only image enforcement and controller network provisioning still needed. No shared writable root across MIs. The helper checks exact canonical root spelling; it does not independently verify the entire image digest at launch.
- `bin/stage-image.sh`: Jammy-only build-host packager for a prepared minimal root, reviewed runner SHA-256 and versioned contract. It deliberately refuses to run on other OS versions, and does not download/install dependencies or construct the prepared root. Output is a tar of an operator-approved root and SHA-256, with no-clobber publication. Use a private build workspace, frozen tree, a trusted output directory outside the input root, no secrets in the image. Install signed/verified estate kits in the prepared Jammy minimal root before packing. Actual image build, full manifest attestation and extraction/commissioning are not yet implemented here. No build tools to be installed on cats.
- `tests/test.rex`: actual native detached disposable sleep children, pidfd lifecycle, eventmux registrations, real LogService logging and controlled registrar fixture. No RTO2 jobs or live namespaces tested.

## Controller contract

The host injects an existing authorised logger and trusted registration adapter, e.g.:

```rexx
backend = .MiChildBackend~new('/opt/rexxos-mi/bin/mi-namespace-exec')
launcher = .MiLauncher~new(muId, backend, registrar, logger, 2)
spec = .MiLaunchSpec~new(miId, muId, incarnation, serviceName, commissionedRoot)
status = launcher~start(spec)
status = launcher~poll(miId)
```

The owning controller supplies all identifiers, fresh incarnation and root path from commissioning and its journal, not an arbitrary remote job. Service name is canonical commissioned service identity, not carrier IP. `start` returns STARTING only when a native handle has been acquired, or UNCERTAIN when a started child could not be pinned; uncertain instances occupy a slot until observed reaped, never fall back to numeric PID signals. STARTING is not REGISTERED. `registrar~observe(id, owner, incarnation, service, processIdentity)` must return .nil if not confirmed, otherwise a Directory VERIFIED=.true, MI, MU, INCARNATION, SERVICE and PROCESS_IDENTITY. This is a trusted in-process interface: real adapter must validate authenticated registration, current membership, proof freshness and correspondence to the launched guest, not copy fields from a caller. The exact existing grid adapter must be supplied and qualified by controller owner. No authentication performed by MiLauncher. On absence of registration evidence poll returns STARTING; on verified matching evidence logs MI_REGISTERED and returns REGISTERED. Logging failures quarantine and block new launches; safety stop of an existing pinned child remains available. Stop matches incarnation, signals retained pidfd, confirms exit, then reaps with original runner; timeout returns STOP_UNCONFIRMED. No automatic restart or force escalation. Current start/stop and registration memory is process-local, history bounded; no restart reconciliation or durable incarnation uniqueness. External controller must maintain that authority and launch timeout. Discarded child stdio is not logging; real runner must deliver its own structured logs from boot, and startup errors need a host diagnostic route.

`exitSources` returns live handle references with MI and INCARNATION for trusted controller event loop. Register with existing persistent mux, on event invoke `poll`; retain current source association and unregister on exit. No claims of full native event bus integration.

## Image and runner integration gate

Build host R3 (Ubuntu 22.04): prepare stock minimal root with approved ooRexx, RTO2 runner, logging and existing authenticated service/registration transport, and `/etc/rexxos-mi/contract-v1`. Install `/opt/rexxos-mi/bin/runner` as reviewed executable entry adapter; it is called with MI, MU, incarnation, service name as separate arguments, remains foreground as PID 1, supervises/reaps any child and hands authority to existing RTO2 runner. It must not accept jobs until membership and existing Job-to-Node lease checks are valid. No SSH server or build tools in MI. Do not copy commissioned identity secrets into the image. `bin/stage-image.sh prepared-root output.tar runner-sha256` packages it. Controller must verify entire image digest, create fresh private writable instance roots and provision the commissioned runtime identity separately using existing approved contracts. A new private network namespace starts isolated; the owning controller must arrange authenticated connectivity to its existing xtpd/service registration path. No bypass, no host network sharing or invented service descriptor. Need exact accepted runner/registration contract and cats2 namespace/KVM capability from Codex/Claude before field integration. No actual image produced or runner adapter included because that authority/runtime is not present in local kit. Existing ED209 candidate3 handler and RTO2 core are referenced, not substituted by a toy runner or copied older segmented XTP path.
