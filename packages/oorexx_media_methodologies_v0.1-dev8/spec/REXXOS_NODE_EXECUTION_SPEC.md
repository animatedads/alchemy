# RexxOS Node Execution for Media Methodologies

RexxOS Grid exposes first-class MU and MI membership.  Media processing should use **MI members as discoverable execution resources**, while retaining their parent MU and incarnation identities.

The media integration records RexxOS evidence but does not infer eligibility from mere membership.  The path is:

1. discover current MI membership from RexxOS Grid;
2. obtain provider-specific implementation requirements;
3. combine those with legal/trust/authority constraints;
4. project them into Job-to-Node;
5. let Job-to-Node authoritatively assess capacity/admission and issue a lease;
6. execute the work unit against referenced Storage/Memory Fabric material;
7. retain node semantic reference, incarnation and placement reference in provenance.

## Why this helps experimental media work

Experimental reconstruction is frequently embarrassingly parallel at the **method branch** level even when one method contains stateful windows.  RexxOS nodes make it practical to run several hypotheses without declaring one algorithm the winner in advance.

For example, a motion-blurred subject may generate six independent branches.  Node A can run leading-edge backprojection, B bidirectional envelopes, C multi-frame latent reconstruction, D flow-warp accumulation, E strip mosaic, and F a model-assisted provider.  The outputs remain distinct candidates and later enter consensus/disagreement analysis.

## Incarnation fencing

A RexxOS semantic node reference is insufficient by itself for provenance.  The MI incarnation must also be retained.  Evidence generated by an earlier incarnation must not silently become evidence from a reincarnated MI with the same member id.
